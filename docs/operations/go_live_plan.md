# Phase-Momentum H5 上线路线图

> 状态：**provisional（tier 2「风险变体」）**。截至 2026-10-09，冻结规格 `PR2026-10-H5`
> 通过了预注册 kill criterion、PBO、成本压力、参数邻域与样本外起点检查，但**没有通过
> Deflated Sharpe（DSR）**。本文把「怎么才能上线」拆成可执行的步骤，并指出哪些是工程问题、
> 哪些是**只有项目负责人能做的规则决策**。
>
> 本文不改任何策略规则、窗口或门槛。所有数字来自 `RESEARCH.md` 与
> `reports/phase_momentum_*`。

---

## 0. 一句话结论

**策略本身已经做完能做的优化；现在卡住的不是策略，是验收规则。**

DSR 用项目真实的 **N = 6,138** 个 Top20/2022 试验做选择偏差惩罚，在这个 N 下，
即使策略保持样本内水平，也还需要 **约 6.4 年**的新数据才能到 0.95（见 §1）。
所以「继续等 DSR 过关」在工程上不是一个计划。

要在合理时间内上线，必须先由项目负责人决定验收规则（§2），然后按 §3–§6 执行。

## 1. 硬阻碍：DSR 在当前试验数下不可达

工具：`scripts/analyze_dsr_horizon.py` → `reports/phase_momentum_dsr_horizon/`。
方法：保持 H5 日收益的**形状**（波动、偏度、峰度）不变，只改变新数据的均值，
把 6,138 次试验的期望最大 Sharpe（年化 **1.184**）作为门槛，重算合并样本的 DSR。

### 1.1 保持样本内 Sharpe（1.623），需要多久

| 新增 OOS | 合并样本 | DSR |
| ---: | ---: | ---: |
| 0 天 | 1,725 | **0.858** |
| 365 天 | 2,090 | 0.881 |
| 730 天 | 2,455 | 0.899 |
| 1,095 天 | 2,820 | 0.915 |
| **2,340 天（6.4 年）** | 4,065 | **0.950** |

### 1.2 如果新数据的 Sharpe 更高

| 假设的 OOS 年化 Sharpe | 达到 DSR 0.95 所需天数 | 年数 |
| ---: | ---: | ---: |
| 1.40 | > 10,000（≈27 年） | — |
| 1.60 | 2,618 | 7.2 |
| **1.623（＝样本内）** | **2,340** | **6.4** |
| 1.80 | 1,232 | 3.4 |
| 2.00 | 776 | 2.1 |
| 2.20 | 562 | 1.5 |

**读法**：DSR 把「从 6,138 个候选里挑出最好的」这个选择惩罚**再收一次费**，
而且收在整个样本上。只要新数据的 Sharpe **不超过**样本内水平，合并 Sharpe 会被拉低，
DSR 上升极慢。这不是「差一点」，是**结构性不可达**。

### 1.3 对比：只用样本外的检验便宜得多

样本外窗口**没有参与选规格**，所以它的 Sharpe 是无偏估计，不需要再付一次选择惩罚。
同样假设 Sharpe ≈ 1.6：

| 检验 | 所需 OOS | 年数 |
| --- | ---: | ---: |
| 单侧 t 检验 95% | 386 天 | **1.06** |
| 单侧 t 检验 99% | 772 天 | 2.11 |

差约 **6 倍**。这就是 §2 决策的核心。

## 2. 需要项目负责人决策的规则问题（必须先做）

`AGENTS.md` 的原文是：多重检验/选择偏差分析「such as White's Reality Check,
Deflated Sharpe Ratio, **or an equivalent documented method**」，
并且要求「nested walk-forward or **genuinely out-of-sample** splits」。

也就是说，规则本身**允许**用等效方法；但规则也写了
「Never weaken, reinterpret, or remove a constraint after seeing a backtest result」。
所以这里**不能由我自行把 DSR 换掉**。必须由负责人现在二选一：

| 选项 | 内容 | 后果 |
| --- | --- | --- |
| **A. 维持现状** | DSR ≥ 0.95 是硬门槛 | H5 在本项目历史试验数下**实际上永远无法上线**；只能一直做 provisional 的样本外记录 |
| **B. 批准等效验收协议** | 现在（在看结果之前）预声明一套**样本外**验收协议（§3），DSR 继续报告但不再作为唯一门槛 | H5 可以在 **12–18 个月**的真实样本外之后，按事先写死的判据决定是否上线 |

**我的建议是 B**，理由：DSR 的 N 里包含大量早已废弃的探索性试验，把这些全部计入
「为选 H5 而做的试验」，在统计上保守到失去判别力；而真正干净的证据恰恰是冻结之后的样本外。
但**这个判断必须由负责人批准，并且必须现在批准**——等样本外攒到能看出结论时再定规则，
就是事后挑口径，规则本身不允许。

## 3. 推荐路径 B：预声明样本外验收协议

**必须在样本外窗口仍无信息量时（现在，17 天）写死。** 任何一条改动都会重置计时。

- **冻结对象**：`PR2026-10-H5`，`PhaseMomentumSpec` 与 `PRIMARY_SIGNAL_SPECS` 一律不动。
- **起点**：2026-09-22（研究截止日之后的第一天）。
- **口径**：20 bps，+1h 成交（若 §4 落地；否则 +3h 较差缺 K 线口径），BTC 为基准。
- **最小长度**：**365 天**（1 年）。不足 365 天不作任何上线判定。
- **主判据（必须过）**：
  1. OOS 年化 Sharpe 的单侧 t 检验 **> 0，95% 显著性**（`t = SR × √years`）。
  2. OOS Sharpe ≥ **0.5 × 样本内 Sharpe**（效应量没有崩塌）。
- **次判据（必须过）**：
  3. OOS 终值 ≥ BTC 同期终值。
  4. OOS 最大回撤 ≤ **50%**（样本内为 -37%，留 13pp 容差）。
  5. 全部 OOS 期间**零参数改动**、零规则改动、零成本口径改动。
- **同时报告、但不作唯一门槛**：DSR（当前 0.858）、White Reality Check、逐币归因、
  滚动 1 年最差。
- **失败处理**：任一条不过 → 继续记录，不得用「换个起点」「换个成本」救回来。

预注册模板（登记进 `reports/research_trial_inventory/preregistered_trials.csv` 或
`docs/research/` 下的 OOS 协议节），在协议生效前不得查看 OOS 结果。

## 4. 执行杠杆：把成交从 +3h 提前到 +1h（不改规则）

这是目前**唯一免费的大杠杆**，纯运营：

| 口径（20bps） | 总收益 | Sharpe | 最大回撤 |
| --- | ---: | ---: | ---: |
| +3h（现状） | 19.53x | 1.623 | -37.0% |
| **+1h（目标）** | **22.80x** | **1.704** | **-33.3%** |

前提与步骤：

1. **测出 CMC 的 T90**：`scripts/probe_cmc_publication.py`（launchd 每 15 分钟一次，
   00:05–03:50 UTC）已在跑；需要 **7–10 天**的数据算出「≥90% 样本拿到 D-1 的最早时刻」。
2. 若 T90 ≤ 01:00 UTC：把 `ops/com.atlas20.daily-refresh.plist` 的刷新时点提前到 T90 之后，
   并把实盘成交定在刷新完成后约 1 小时。
3. **重新验证**：用 `scripts/run_phase_momentum_execution_lag.py` 以 +1h 口径重跑，
   确认 Sharpe / MDD 与文献表一致，并确认 `observed_weight_share`（有小时 K 线的成交权重）够高。
4. **写进 runbook**：刷新时点、成交时点、失败回退（若刷新未完成 → 用 +3h，不裸奔）。

> 注意：这一步只改**什么时候下单**，不改**下什么单**，所以不算新试验，也不抬高 N。

## 6. 资金与风险分层

H5 的**真实形态**是「1–2 个币的轮动」：有仓位时平均持 **1.99** 个币，90% 的持仓日
最大单币 ≥50% 组合，前 5 个币贡献 **90.3%** 的收益，去掉 SOL 就从 19.5x 掉到 6.6x。
回撤 -37% 就是这种集中度的价格。上线必须按这个事实配资金：

1. **影子期（≥30 天）**：只生成信号、记录假设成交，不下真单。核对引擎权重与
   理论成交的可实现性。
2. **小额期（目标资金的 5–10%）**：真单，但只用来验证执行链路与对账，不追求收益。
3. **逐步加仓**：每满足一个季度不触发熔断，按事先写死的步长加；**不加杠杆、不做空**。
4. **风险预算**：因为单币集中，用「可承受的最大回撤」反推资金，而不是用收益率反推。
   若可承受 -20%，则因为规格 MDD 为 -37%，资金规模应为风险预算的约一半。
5. **熔断**：运营级（非策略级）总开关，触发条件与恢复条件上线前写死。

> 若要给策略**本身**加回撤熔断，那是一条新规则 = 新试验，会把 N 抬高、
> 让 DSR 更远。所以熔断只做在运营层，不进规格。
