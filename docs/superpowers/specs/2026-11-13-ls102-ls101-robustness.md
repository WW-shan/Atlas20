# Atlas20 预注册：LS101 稳健性审计

| 项目 | 内容 |
|---|---|
| 日期 | 2026-11-13 |
| 状态 | 已预注册；robustness audit；research-only |
| Trial ID | `PR2026-11-LS102-LS101-ROBUSTNESS` |
| 候选 | LS101 100% residual、10bps 主档（LS57 固定 20bps）+ 20/50/100bps basis 压力 |
| 对照 | 同一 LS57 frozen baseline，不改变任何选币/权重/stop/gross 规则 |
| 窗口 | 2022-01-01 → 2026-09-20 |
| 目的 | 检查 LS101 的增量是否集中在单年/单窗口，并在更高执行成本下是否仍成立 |

## 0. 冻结逻辑

LS102 不产生新策略配置，只审计 LS101 100% residual。成本压力只改变 LS100 basis sleeve 的
每腿每边成本，LS57 仍保持 20bps；不扫描 allocation、gross cap、funding filter 或资产集合。

## 1. 必做检查

1. 10/20/50/100bps 下 full 终值和 Sharpe 均高于同窗口 LS57；
2. 每个日历年分别比较 LS101 与 LS57，至少 4/5 年 LS101 终值更高；
3. 删除最佳年份（按 LS101 相对 LS57 的年度超额选定）后，LS101 仍高于 LS57；
4. 365 个日观测滚动窗口：LS101 胜率 >=75%，最差滚动窗口的终值不落后 LS57 超过 2%，
   且最差 MDD 差值不超过 2pp；
5. 月度起点到样本末：至少 75% 起点 LS101 终值更高，最差 MDD 差值不超过 2pp；
6. 组合 gross 始终 <=1.45x，收益/成本/日期无缺失或非有限值。

所有检查同时通过才记为 `pass`。任何一项失败记为 `robustness-fail`，不接实盘；不回扫参数
救结果。通过也只表示 LS101 在同 venue 价格 + funding proxy 下不是单年/单窗口幻觉，仍不解决
完整历史 Bitget funding、真实成交、保证金或 liquidation 问题。

## 2. 输出

- `summary.csv`：每项检查的数值和 pass/fail；
- `yearly_comparison.csv`：逐年 LS101 vs LS57；
- `rolling_365d.csv`：滚动窗口胜率、最差终值和 MDD 差值；
- `monthly_starts.csv`：月度起点比较；
- `report.md`、`manifest.json`。

## 3. 复现

```bash
.venv/bin/python scripts/run_ls102_ls101_robustness.py \
  --output-dir reports/ls102_ls101_robustness_2026
```
