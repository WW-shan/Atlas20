| 负责人决定 | 2026-11-15 明确要求采用 0.90 margin cap、4x venue leverage 和 S050/G175；50bps 是硬压力测试上限，100bps 仅保留为诊断 |

## 1. 冻结构造

除以下参数外，LS104 完全继承 LS45：

```text
H5 long target:                 1.25x
bear weak-four short request:   0.50x total = 4 x 0.125x NAV
non-bear funding-exit request:  0.50x total = 0.05x NAV per active leg,
                                 capped at 0.50x total request
max_total_gross:                1.75x
long_buffer:                    0.50
short_buffer:                   0.50
max_margin_utilization:         0.90
venue leverage:                 4x isolated
short stop:                     20% mark-price market stop
rebalance:                      T+1 01:05 UTC; weak-four every 7D
```

所有 schedule 事件上的短头总权重必须在 `combine_long_with_cash_budgeted_short` 之前截断到 0.50x。多头仍优先占用 gross；空头只使用总 gross cap 下的剩余容量。

## 2. 保证金数学

`initial_margin_ratio = 0.50 + 0.01 maintenance + 0.005 fee = 0.515`。

```text
1.75 * 0.515 = 0.90125x equity
0.90 margin cap -> 0.90 / 0.515 = 1.74757x maximum funded gross
```

因此 1.75x 目标在 0.90 cap 下只缩到 1.748x，按实际执行视为接近满额。满额时权益的约 90% 被锁为 isolated margin，约 10% 保留为自由权益。

4x 只是 venue 的最大杠杆上限；因为 LS104 显式维持 50% buffer，实际每腿保证金仍是名义的约 51.5%，不是 25%。因此 4x 不会把多头强平距离缩短到 25%。

## 3. 风险边界

- 组合实际 gross 必须 `<= 1.75x equity`。
- 任一时刻的 isolated margin utilization 必须 `<= 0.90`；执行器若触发缩放，必须在报告中明确记录。
- 每腿必须 isolated；venue leverage 必须是 4x；每腿实际 margin/notional 不低于 45%。
- 每个当前空头必须有且只有一张覆盖完整仓位的 20% mark-price market stop。
- 未确认止损、孤立策略单、重复止损、计划外普通单、数据新鲜度失败、manifest 指纹失败或 account binding 失败全部 fail closed。
- 若发生 gross breach、强平、止损失效或账本对不上，必须写 kill switch 并停止新风险。

LS104 的 20bps 和 50bps 结果必须报告；100bps 只作为 diagnostic，不进入 promotion gate。

## 5. 验收

### 5.1 工程门禁

1. 新 track 不修改或覆盖 `LS45-G125` 的 manifest、targets、state、journal 或 audit。
2. 新 target ledger 的事件、权重、短头总请求、manifest spec、frozen config、data fingerprint、targets hash 全部一致。
3. 新 executor 使用 4x venue leverage、0.90 margin cap、50% buffers、20% stop；所有 fail-closed 检查仍启用。
4. dry-run 计划中每个空头的 stop、margin、liquidation distance、quantity 和 gross 都能复算。
5. 20bps 和 50bps live-parity 重跑后记录 metrics、gross、margin scaling、quantization、skips、liquidations。
6. `make test`、`make lint`、`make typecheck`、前端测试通过；relevant targeted tests 先红后绿。

### 5.2 Live 门禁

1. 最新数据 audit 0 hard failure；不可使用 stale mark 或旧 panel。
2. 新 target event 已在正常 01:05 UTC 窗口内可执行；默认不做历史事件的事后追单。
3. 账户 isolated、4x、无未成交普通单、无非法重复腿。
4. 执行前 dry-run 证明：0 margin-cap scaling（或记录 <=0.1% 的 rounding scale）、0 gross breach、每个短头一张 stop。
5. 执行后 `audit-live` 0 hard failure；targets hash、manifest、state、journal、exchange order history 全部一致。
6. 任何一项失败：保持旧 LS45-G125 运行路径，kill switch，人工核对。

## 6. 回滚

LS45-G125 的文件和 state 保持原封不动。LS104 的 ops profile 可以切回 `ls45-g125`，不需要恢复旧 journal；但已经发生的 LS104 仓位必须先按当前目标减到 LS45 的 S025，再切回旧 track，绝不能只切配置留下超风险仓位。
